## 1. 요약

1. **운영사**: 위멤버스는 **웹케시(주)/웹케시그룹**이 운영하는 세무사 전용 업무 플랫폼이다. 2019년 "위 멤버스 클럽"으로 출시했다. [보도]
2. **공개 API/파트너 API**: 공개 API, 개발자 문서, 제휴 API 공고는 **찾지 못했다 → 미확인(UNVERIFIED)**. 외부 연동으로 확인된 것은 같은 그룹 서비스(경리나라)와 제휴사 서비스(로움아이티 "세모리포트". 웹케시 계열 여부는 미확인)와의 연동, 그리고 카카오톡 채널 연동뿐이다. [공식][보도]
3. **수집 방식**: 세무사무소 인증서(세무대리인 관리번호)와 수임동의를 이용해 **홈택스를 자동 스크래핑**한다. 대상은 홈택스·위택스·공단 자료이며, 매월 지정일 06시 스케줄러와 실시간 조회를 지원한다. 수집 경로는 주로 홈택스 `세무대리 > 세무대리 공통` 메뉴다. [공식(검색 요약)]
4. **다운로드**: 홈택스 통합자료는 **엑셀 다운로드**와 거래처별 **PDF/이미지 일괄 다운로드**를 지원한다. 신고리스트 화면에서는 **접수증·신고서·납부서**를 건별로 받거나 여러 건을 일괄로 받을 수 있다. 일괄 다운로드는 ZIP 파일 안에 거래처별 폴더로 만들어진다는 설명이 있으나 원문은 미확인이다. [공식(검색 요약)]
5. **위멤버스 엑셀 컬럼 레이아웃**: 공개 자료로는 **확인 불가 → 미확인**. 실제 샘플 파일을 확보해야 한다.
6. **홈택스 원본 엑셀 레이아웃**(파일 어댑터에 핵심)
   - **전자세금계산서 목록조회 엑셀**: 헤더가 **6행**에 있다는 점은 커뮤니티 코드 3건(mintoffice·Wandongkee·swkang87)에서 일치한다. 반면 **33개 컬럼 순서(0-index)는 swkang87 주석 1건에만 근거**한다. 2013년 mintoffice 레이아웃은 맨 앞에 `번호` 열이 있고 `주소` 열이 없어 **서로 다르다**. [커뮤니티] (팩트체크로 정정)
   - **사업용 신용카드 매입세액 공제 확인/변경 엑셀**: 14개 컬럼이다. `승인일자, 카드사, 카드번호, 가맹점사업자번호, 가맹점명, 공급가액, 세액, 비과세, 합계, 가맹점유형, 업태, 업종, 공제여부결정, 비고` [커뮤니티]
     - 요청서가 가정한 `부가세/봉사료` 컬럼은 **관찰되지 않았다**. 관찰된 이름은 `세액/비과세`다.
   - **현금영수증 매입내역**: 필드 목록만 부분적으로 관찰했다(스크래핑 코드 기준). 엑셀 헤더 원문은 미확인이다. [커뮤니티]
7. **규제 환경(2025~2026)**
   - 국세청은 2025년 5월 홈택스 스크래핑 대응 ISP 사업을 발주했다. 오픈 API 설계와 국세데이터 이용수수료 설계가 포함되어 있다. [보도]
   - **2026-08-20 시행** 개인정보 보호법 시행령(대통령령 제36121호, 2026-02-19 공포, "공포 후 6개월이 경과한 날부터 시행")에 따라, 정보주체의 대리인이 **자동화된 도구**로 본인전송요구를 하면 본인대상정보전송자(공공시스템운영기관 등)와 **사전에 협의한 방식**으로 전송해야 한다. 또한 대리인은 개인정보를 **저장하지 않고 본인에게 전달**해야 한다(제42조의6제3항제1호나목·제5항). [공식(법령 미러)] 보도는 이를 "사전협의 없는 스크래핑 제한"으로 요약했다. [보도] 이 조항이 세무대리인의 홈택스 수임자료 수집에 그대로 적용되는지는 **미확인**이다.
   - 따라서 MIN TAX OPS가 홈택스를 직접 스크래핑하는 방식은 **권장하지 않는다**.
8. **권장 연동 상태**: 위멤버스 API는 **NOT AVAILABLE**이다. 주 경로는 **FILE BASED**(사람이 다운로드 → 폴더 감시/업로드 → 파서)로 두고, 개발·테스트에는 **MOCK**을 쓴다. 위멤버스 웹 **RPA는 보류**한다(약관 미확인). 홈택스 직접 스크래핑은 **NOT AVAILABLE(정책상 배제)** 로 둔다.

#### (C) 현금영수증 매입내역(지출증빙) 엑셀

- 메뉴: `[전자(세금)계산서·현금영수증·신용카드] > [현금영수증] > … > [사업자] > [매입내역(지출증빙) 조회]` → `엑셀 내려받기` [검색 요약] https://help.bznav.com/hc/ko/articles/900007648743
- **필드 관찰(부분)**: GitHub `kaimen83/clinicmanager2`의 `lib/models/HomeTaxCashReceipt.ts`(홈택스 크롤링 결과 저장 스키마). **엑셀 헤더가 아니라 크롤링 필드명**이다. [커뮤니티]
  - `매입일시, 사용자명, 가맹점사업자번호, 가맹점명, 업종코드, 업종, 업태, 공급가액, 부가세, 봉사료, 매입금액, 승인번호(unique), 발급수단, 거래구분, 거래일자, 가맹점납세자통합관리번호, 공제여부`
  - 크롤링 스크립트(`app/api/hometax/crawl-script/route.ts`)에는 `사용구분`, `비고`도 있다.
  - `app/api/hometax/verify/route.ts`는 `receipt.매입금액 || (공급가액 + 부가세 + 봉사료)`로 은행 거래금액과 매칭한다. 이는 **매입금액이 비었을 때 쓰는 대체 계산**이다. 두 값이 같은지 검사하는 **검증식이 아니다**. (팩트체크로 정정: 이전 판은 "금액 검증식"이라고 적었음)
- (팩트체크 추가) `finecodekr/hometaxbot` `scraper/transactions.py`의 `현금영수증()`에서 관찰한 내용이다. [커뮤니티]
  - **매출** 쪽은 다운로드 요청(`downloadView: 'Y'`)으로 받는다. 응답은 **탭 구분 텍스트(UTF-8)**이고, 첫 줄은 요약이라 건너뛴다.
  - 매출 헤더명: `매출일시, 공급가액, 부가세, 봉사료, 총금액, 승인번호, 발행구분, 거래구분, 비고, 신분확인뒷4자리`
  - **매입** 쪽은 JSON으로 받는다(screenId `UTECRCB005`). 필드는 `aprvNo`(승인번호), `splCft`, `vaTxamt`, `tip`, `totaTrsAmt`, `trsClNm`, `cshptTrsTypeNm`, `prhTxamtDdcYn` 등이다.
  - 브라우저의 "엑셀 내려받기" 파일이 같은 형식인지는 **미확인**이다.
- 홈택스 현금영수증 **매출**내역 엑셀은 WEHAGO T에서 그대로 불러올 수 있다(조회발급 > 현금영수증 조회 > 매출내역조회 > 엑셀 내려받기). 매입 엑셀을 불러올 수 있는지는 미확인이다. [공식(WEHAGO T 도움말, 검색 요약)] https://wehagothelp.zendesk.com/hc/ko/articles/10748413395225

### 4.2 파일 어댑터 설계 요구사항

1. **헤더 행 자동 탐지**: 행 번호를 고정하지 않는다. 상위 20행에서 앵커 조합으로 헤더를 찾는다(세금계산서 `작성일자`+`승인번호`+`공급가액`, 사업용카드 `승인일자`+`가맹점사업자번호`+`공제여부결정`). 관찰값은 세금계산서 6행, 사업용카드 샘플 2행이다(2.5-B, 샘플 편집 가능성 있음).
2. **중복 헤더명 처리**: 세금계산서 엑셀은 `종사업장번호/상호/대표자명/주소`가 공급자와 공급받는자에 **두 번씩** 나온다. 이름만으로 매핑하지 말고 **순서(position) + 앞 컬럼 문맥**으로 매핑한다(pandas `상호.1` 문제).
3. **레이아웃 지문(fingerprint)과 버전 관리**: 정규화한 헤더 목록의 해시를 레이아웃 ID로 저장한다. 알려지지 않은 지문은 **격리 큐**로 보내고 알림을 띄운다. mintoffice의 `기타` 컬럼 같은 변형(2.5-A)에 대비하기 위함이다.
4. **정규화**
   - 사업자번호: `111-22-33333`과 `1112233333`를 모두 받아 10자리 숫자로 바꾼다.
   - 금액: 쉼표가 들어간 문자열(`1,000`)과 음수(수정세금계산서)를 처리한다.
   - 날짜: `YYYY-MM-DD`와 `YYYYMMDD`를 모두 받는다.
   - 카드번호: 마스킹된 값이 올 수 있으므로 원문을 그대로 저장하고 식별키로 쓰지 않는다.
5. **멱등키(idempotency key)**
   - 세금계산서: `승인번호`(+매입/매출 방향). 한 승인번호가 여러 품목 행으로 나올 수 있으면(U6) 행 단위 키는 `승인번호+행 순번`으로 하고, 문서 단위 키는 `승인번호`로 한다. [추론]
   - 현금영수증: `승인번호`. 취소거래와 승인거래가 공존할 수 있으니 `거래구분`을 포함한다. [추론]
   - 사업용카드: 관찰된 엑셀에 **승인번호 컬럼이 없다**. 복합키 `승인일자+카드번호+가맹점사업자번호+합계+동일키 내 순번`을 쓴다. [추론] (화면 JSON에는 거래내역 일련번호 `busnCrdcTrsBrkdSn`이 있으나 엑셀에는 관찰되지 않음, 2.5-B)
6. **파일 형식**: xls(BIFF), xlsx, HTML 테이블 위장 xls, 탭 구분 텍스트를 매직바이트/내용으로 판별한다(U4). 원본 파일은 해시와 함께 **불변 보관**한다(감사 추적).
7. **금액 검증 규칙**
   - 세금계산서: `합계금액 = 공급가액 + 세액`
   - 사업용카드: `합계 = 공급가액 + 세액 + 비과세`. 이는 관찰된 예시값 1,000 + 100 + 0 = 1,100에 근거한 [추론]이다.
   - 현금영수증: `매입금액 = 공급가액 + 부가세 + 봉사료`. 이는 [추론]이다. 커뮤니티 코드(clinicmanager2)는 이 합을 매입금액이 **비었을 때의 대체값**으로만 쓴다(2.5-C).
   - 불일치 행은 경고로 표시하되 적재는 한다.
8. **공제여부 필드 보존**: 사업용카드 `공제여부결정`(공제/불공제)과 `비고`(예: 선택불공제)를 그대로 저장한다. 이 값은 WEHAGO 전표의 공제·불공제 구분으로 전달된다.

### 4.3 WEHAGO 방향 시사점

- WEHAGO T는 **홈택스 원본 엑셀을 그대로 불러올 수 있다**. 사업용카드 공제확인 엑셀과 현금영수증 매출 엑셀이 해당한다(2.5-B, C). 또한 전자세금계산서는 **자체적으로 자동 수집**한다(2.7).
  - → MIN TAX OPS는 위멤버스 데이터를 WEHAGO 형식으로 "변환해 밀어넣는" 기능보다 다음 역할에 집중하는 편이 위험이 적다. [추론]
    - ① 파일 수집·검증·보관
    - ② 위멤버스 합계와 WEHAGO 전표 사이의 **대사(reconciliation)**
    - ③ **원본 파일을 그대로 전달(pass-through)** 하는 워크플로 관리
- WEHAGO 측 업로드 규격은 별도 조사 문서에서 확인한다. 예를 들어 WEHAGO T의 일부 엑셀 서식은 Excel 97-2003 형식에 2MB 제한이 있다는 안내가 있다. https://wehagothelp.zendesk.com/hc/ko/articles/10748413395225

### 4.4 운영·보안

- 세무대리인 인증서와 관리번호 비밀번호는 MIN TAX OPS에 **저장하지 않는다**. 로그인은 위멤버스나 홈택스에서 사람이 직접 한다.
- 수임 권한 오류코드(C5: 80007180/80003720/80002251)를 **"사람이 해결할 일" 체크리스트**로 노출한다. 대표적 원인은 관리번호 불일치다.
- 신고기간 스크래핑 지연·차단 보도는 **미확인(UNVERIFIED)**이다. 이전 판은 R1을 근거로 들었으나, R1(ISP 발주 보도)은 이를 뒷받침하지 않는다. [추론] 그래도 위멤버스 스케줄러 결과가 늦을 수 있다고 가정한다. 수집 SLA를 느슨하게 잡고, 수동 업로드 경로를 상시 열어 둔다.
- 개인정보(주민번호가 포함될 수 있는 종소세 자료 등)는 최소 수집하고 마스킹한다. 2026-08-20 시행 시행령 제42조의6제5항(대리인 비저장 의무, R4)의 취지를 고려해 보관 기간 정책을 문서화한다.
